# T2i display — Himax HX8347 (8-bit FSMC)

The T2i's 2.8" 320×240 panel is driven by a **Himax HX8347** controller on an
8-bit Intel-8080 parallel bus wired to the STM32's FSMC. This documents how we
know that, and what the reverse-engineered init sequence actually does.

## Identifying the controller

`lcd_read(0x00)` returns **0x47**. On the HX8347, register `R00h` is the
device-code / ID register and reads back `0x0047`. That, plus the register
map used by RTI's init, is a positive HX8347 identification:

| Feature | HX8347 | Matches RTI? |
|---|---|---|
| ID register R00h | `0x47` | ✅ `lcd_read(0)=0x47` |
| Window registers | `R02h–R09h` (column/row start & end) | ✅ |
| GRAM write | `R22h` | ✅ (`lcd_cmd(0x22)` before pixel stream) |
| Gamma control | `R40h–R5Dh` | ✅ (RTI writes all of these) |
| Power control | `R1Bh/R1Ah/R18h/R19h/R1Fh` | ✅ |
| Display control | `R26h/R27h/R28h` | ✅ |

There is **no mainline Zephyr HX8347 driver**; `drivers/display/display_hx8353e.c`
(HX8353E) is the closest Himax sibling for style reference. Arduino
`MCUFRIEND_kbv` drives the HX8347 over an 8-bit parallel bus almost identically
to our FSMC setup and is a good cross-check for the gamma/timing values.

## Bus wiring (FSMC bank1 / NE1, 8-bit)

- Command/index write → `*(uint8_t*)0x60000000` (A18 low)
- Data write → `*(uint8_t*)0x60040000` (A18 = PD13 = RS/DC high)
- `BCR1 = 0x1049` (MBKEN, MWID=8-bit, MTYP=NOR, FACCEN, WREN)
- `BTR1 = 0x00102D11` (ADDSET/DATAST timing, from RTI)
- Data bus PD14/PD15/PD0/PD1 + PE7–PE10; RD=PD4, WR=PD5, CS=PD7, RS=PD13 (all AF12)
- **PD6 = hardware reset** (GPIO): pulse low ≥10 ms, high, wait 150 ms before init

A 16-bit RGB565 pixel is written high-byte then low-byte (two 8-bit data writes).

## The init sequence, explained

Reversed from stock RTI (`FUN_0800f610`, the `id==0x47` branch) and replicated
in `src/hx8347_fsmc.c :: panel_init()`. `reg(c,d)` = write value `d` to register
`c`.

```
EA=00 EB=20 EC=0C ED=C4   ; power/OSC internal-use timing (Himax app-note values)
E8=40 E9=38               ; source/gate driving timing (SAP / cycle)
F1=01 F2=10               ; internal control (VCOM/charge-pump options)
27=A3                     ; display mode / driver-output control
40..4C = 01 07 06 0A 0C 3D 02 43 07 14 19 1A 1E   ; positive gamma curve
50..5D = 02 33 35 39 38 3E 3C 7D 01 05 06 0B 18 FF ; negative gamma curve
1B=1B                     ; power control 2: step-up (boost) factor for VGH/VGL
1A=01                     ; power control 1: BT / step-up circuit config
24=45 25=1F               ; VCOM control: VCOMH / VCOML voltages
23=8A                     ; VMF: VCOM offset
18=36 19=01               ; OSC control: frame rate + oscillator enable
01=00                     ; display mode / scroll off
1F=88 →80 →90 →D0 (5 ms each) ; power-control 6: bring up the internal supplies
                          ; in the Himax-specified order (GAS/VCOMG/PON/DK bits)
16=40                     ; MADCTL: memory access — row/col/RGB order & flip
17=05                     ; COLMOD: pixel format = 16bpp (RGB565)
36=02                     ; panel characteristics / gate scan
28=38 (40 ms) →3C         ; display control: turn the display GRAM output on
02..09                    ; window = full screen (col 0..239, row 0..319)
```

Key groups:
- **EA–F2 / 27**: Himax "internal use" and driver-timing registers. These are
  panel-module-specific magic numbers from Himax's reference init; they set
  source/gate timing and are copied verbatim (changing them risks a bad image).
- **40–5D gamma**: two 14-entry curves (positive/negative) that linearize
  brightness. Purely cosmetic — safe to tweak for color/contrast.
- **1A/1B/1F/23/24/25 power**: configure the on-chip charge pumps and VCOM.
  `1F` is stepped `88→80→90→D0` with 5 ms settling so the internal rails come up
  cleanly. **Don't reorder or rush these** — they drive the panel's analog supplies.
- **16 MADCTL**: orientation/mirroring and RGB-vs-BGR. `0x40` = our portrait
  orientation with X as the fast (column) axis. Flip bits here to rotate/mirror.
- **17 COLMOD = 0x05**: 16-bit/pixel. Matches our RGB565 pixel writes.
- **28 display-on**: `0x38` then `0x3C` staggers the GRAM/output enable.

## Backlight (separate from the controller)

The HX8347 does not control the LED backlight. That is a **PWM-dimming input on
PA1 = TIM2_CH2** feeding a backlight driver IC. Brightness = PWM duty (the driver
regulates LED current, so duty only changes brightness, never LED voltage). We
run it at ~30 kHz to stay out of the audible band — the ~2 kHz register state we
first read from RTI was its *idle/dimmed* config and made the boost inductor whine.

## Drawing

1. `lcd_window(x0,y0,x1,y1)` → set `R02h–R09h`.
2. `lcd_cmd(0x22)` → start GRAM write.
3. Stream `w*h` RGB565 pixels (high byte, low byte each). The controller
   auto-increments within the window.

This is exactly what the Zephyr `display_write()` implementation does, which is
how LVGL flushes rectangles to the panel.
